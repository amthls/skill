# Plan Board – contract v2 (LOCKED)

Plan Board is a reusable kit for discussing and planning ANY project on a local web board instead of in text chat.
- **UI:** a fork of the Understand-Anything (UA) dashboard (MIT) plus a "Kế hoạch" tab.
- **AI side:** the AI only writes compact text in `<project>/.board/`. The `board` CLI compiles that text to UA-format JSON.
- Everything is UTF-8 without BOM. Every id matches `^[a-z0-9][a-z0-9._/-]*$` and is stable (the AI edits by id).

## 1. Project files
```
.board/board.json          {"title","subtitle"?,"ua"?}   ua = path (from project root) to a /understand knowledge-graph.json
.board/graph.txt           architecture + flows DSL (AI writes)            §2
.board/pages/NN-<id>.md    discussion pages, sorted by NN (AI writes)      §3
.board/embeds/*            optional bespoke demos (AI writes)
.board/inbox.jsonl         user feedback (SERVER appends only)             §5
.board/.inbox-offset       byte offset already delivered (HOOK/CLI only)
.board/build/              GENERATED by `board build`; never hand-edited, never read by the AI
   knowledge-graph.json  domain-graph.json  pages.json
```

## 2. graph.txt DSL
The file is read line by line. `#` starts a comment, but only at the beginning of a line or after whitespace. Indentation matters only for `fn`.
```
== core: Bộ não | Logic thuần, không DOM         layer header; nodes below belong to it
js/core/cube-model.js : Lưu 54 ô + xoay #model !moderate
  fn applyMove(state, move) -> state : Xoay 1 mặt
  fn parseMoves(str) -> string[]
lib:three [service] : Thư viện 3D (CDN)
== ui: Giao diện
js/ui/net-editor.js : Lưới 2D tô màu
--                                              ends layers; nodes after this have no layer
js/app.js -> js/core/validate.js, js/ui/net-editor.js : gọi    edge(s); one source, several targets
js/ui/cube3d.js -> lib:three [depends_on]
>> flow paint: Tô 1 ô | Người dùng chạm 1 ô trên lưới
js/ui/net-editor.js.onStickerTap : Nhận chạm | vào: index 20 | ra: {index:20,color:"R"}
js/app.js.handlePaint : Gọi người gác cổng
```
Node line: `<ref> [type]? : <summary> #tag* !simple|moderate|complex`
- `ref` that ends in a file extension → type `file`, id `file:<ref>`, filePath `<ref>`.
- `lib:<x>` → type `service`, id `lib:<x>`.
- Anything else → type `concept`, id `concept:<ref>`. An explicit `[type]` must be a UA NodeType.
- Defaults: summary `""`, tags `[]`, complexity `simple`.

`fn` line, indented under a file: id `function:<file>:<name>`, name `<name>`. The signature is kept in the summary: `"(state, move) -> state — Xoay 1 mặt"`. An automatic edge `contains` runs file → function.

Edge line: `<ref> -> <ref>[, <ref>…] [edgeType]? : <description>`
- Edge type defaults to `imports` when both ends are files, otherwise `calls`.
- direction `forward`, weight 0.5.
- A ref may be a file, `file.fn` (a function) or `lib:x`.
- Every ref must already be defined above; anything else is an error.

Flow block: `>> flow <id>: <Title> | <description>`, followed by step lines until the next `>>`, `==` or `--`, or the end of file.
- Step line: `<ref> : <label> | vào: <text> | ra: <text>`. The `vào` and `ra` parts are optional.
- `ref` must be a defined node or `file.fn`.

Compile output (`board build`):
- `build/knowledge-graph.json` in the UA KnowledgeGraph format.
  - `project`: name = board.title, analyzedAt = now, gitCommitHash `"plan"`, languages/frameworks inferred from extensions or `[]`.
  - `layers` come from `==` headers.
  - `tour` is the concatenation of all flows. Each step is `{order, title:"<Flow> · i/n: <label>", description:"<label>\n\nvào: …\nra: …", nodeIds:[nodeId]}`.
- `build/domain-graph.json` in UA domain format (match exactly what `skills/understand-domain` writes):
  - 1 domain node `domain:<board slug>`;
  - each flow → node `flow:<id>`, linked to the domain with `contains_flow`;
  - each step → node `step:<flowId>:<i>` with summary = label + vào/ra, linked to its flow with `flow_step`, plus `domainMeta.entryPoint` = the referenced node id.
- Errors print as `graph.txt:<line>: <message>` and the exit code is 1.

## 3. Page markdown (`pages/NN-<id>.md`)
Page id = file name without `NN-` and `.md`.
```
---
title: Kỹ thuật
lead: Một dòng mô tả trang
---
## Kiến trúc 3 tầng {#arch}
> 🎯 Bạn sẽ hiểu được: …          (first blockquote starting with 🎯 = section lead)
Markdown text (GFM: tables, task lists `- [ ]`, code, links).
```graph
layers: core, ui        # filter, optional
ids: js/app.js          # optional extra filter (refs)
focus: js/app.js        # optional
max: 40                 # optional, default 40; "Mở rộng" + fullscreen in UI
direction: RIGHT        # RIGHT|DOWN
src: plan               # plan (default, build/knowledge-graph.json) | ua (board.ua)
```
```flow
paint                   # flow id from graph.txt; UI = graph + ⏮▶⏸⏭ player + step card (label, vào, ra)
```
```decision id=renderer status=open
? Dùng thư viện 3D nào?
- three: Three.js | Phổ biến, 3D thật
- css: CSS 3D | Nhẹ, không cần thư viện
```
```cards
🎨 Bạn tô màu | Tô lại khối đang xáo
🧠 App suy nghĩ | Tìm lời giải
```
```embed
src: giai-thich/index.html#s4    # path from project root, or http(s) URL
height: 420
```
```
- A section starts at each `##`. Its id is `{#id}` if given, otherwise a slug of the heading (ASCII, unaccented Vietnamese). Section ids must be unique within the page.
- **Decision done:** the fence becomes `decision id=renderer status=done chosen=three`, and an optional line `note: …` is added. Only the AI does this, usually with `board decide`.
- Plain GFM covers steps (ordered list), tables and checklists. Only the 5 fenced block types above are special.

## 4. CLI `board` (node ≥18, zero deps; `node ~/.claude/skills/plan-board/bin/board.mjs`)
| command | effect / output (all output compact, Vietnamese messages) |
|---|---|
| `init [--template blank\|web\|game\|api\|ai\|mobile]` | creates `.board/` from `templates/<t>/`; never overwrites existing files |
| `build` | compiles §2 and §3 into `build/`; prints `OK n nodes, e edges, f flows, p pages` or the errors |
| `check` | build + cross-checks: refs in graph/flow blocks exist, decision `chosen` is a valid option, embed files exist, ids unique |
| `serve [--port 4173] [--no-open]` | build → serve UI + API (§6), watch `.board/` → rebuild → SSE; prints the URL |
| `context` | ≤ 40 lines: pages → section ids/titles, layers with node counts, flows, OPEN decisions, pending inbox count |
| `get <id>` | details of a node ref, `page#section`, flow id or decision id |
| `decide <decisionId> <optionId> ["note"]` | rewrites that decision fence to done (the only CLI write to pages) |
| `inbox [--peek]` | prints new feedback (§5 format) and advances the offset (`--peek` = don't advance) |
| `hook` | UserPromptSubmit entry: finds `.board/` from cwd upward; none → exit 0 silently; otherwise same as `inbox`, header `[plan-board] góp ý mới:`; reads the stdin JSON prompt for `[inbox@N]` |

## 5. inbox.jsonl
One JSON object per line, terminated by `\n`:
```
{"t":"ISO","page":"ky-thuat","sec":"arch","node":"","kind":"comment|choose|edit|ask","val":"","text":""}
```
- `node` is the graph node id when the comment was made on a node in the panel.
- `val` is the option id for `choose`.
- `text` is at most 2000 chars.

Printed/copied format (hook, `inbox`, and the UI "📤 Gửi cho Claude" button):
```
[board ky-thuat] 2 góp ý
- arch: ask "Vì sao tách core?"
- renderer: choose three
- arch@file:js/app.js: comment "node này rối"
[inbox@1234]
```
- Text is cut to 200 chars.
- Output is capped at 20 lines, then `…còn K mục (board inbox)`.
- The offset counts bytes up to and including the last complete `\n`.
- If the prompt contains `[inbox@N]`, the offset becomes max(offset, N) first.

## 6. Server API (`board serve`; the UI uses ONLY these)
- `GET /`: prebuilt `dist/` (static).
- `GET /knowledge-graph.json`, `/domain-graph.json`: served from `build/`. If `?src=ua`, serve `board.ua` instead.
- `GET /api/board` → `{board, pages:[{id,title,lead,sections:[{id,title,lead,blocks:[{kind:"md",md}|{kind:"graph",…}|{kind:"flow",id}|{kind:"decision",…}|{kind:"cards",items}|{kind:"embed",src,height}]}]}], flows:[{id,title,description,steps:[{nodeId,label,in,out}]}]}`.
- `GET /api/events`: SSE. `event: changed` after a rebuild; `event: inbox` after feedback; a ping every 25 s.
- `POST /api/feedback` with `{page,sec,node?,kind,val?,text?}` → appends one line, returns `{ok,pending}`.
- `GET /api/inbox/pending` → `{pending, text}`, where `text` is the §5 copy format.
- `GET /files/<path>`: a file from the project root, for embeds. Path traversal outside the root is rejected.
- Bind to 127.0.0.1 only. If the UA TokenGate is kept, the server injects the token automatically. The user is never asked to type one.

## 7. Hard rules
1. The server never writes anything except appending to `inbox.jsonl`.
2. The AI never edits the kit's UI code for a project. It writes only `.board/` text and embeds.
3. The AI never reads `build/` or `dist/`. To learn the board state it uses `board context` or `board get`.
4. Verification order: run `board check` first; screenshots only when the kit's UI itself changes.
